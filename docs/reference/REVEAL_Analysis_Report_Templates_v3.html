How the report stays consistent.

Two templates that together guarantee report integrity: an Analysis template that computes every finding deterministically — keeping the LLM away from any judgment that must be stable — and a Report template that constrains the LLM to phrasing fixed findings within fixed slots. Built against the Data Schema; doubles as the spec for the analysis engine and synthesis layer.

The pipeline · where the LLM is, and isn't
The one principle. The LLM never decides what is true about a student — not whether something is a surprise, not which capacity is the spike, not whether a gap is Real. Those are computed. The LLM only decides how to say findings it is handed. Move every integrity-critical judgment out of the model, and "the LLM answers differently each time" stops being a threat, because the LLM is no longer answering the questions that must be stable.
Part One

The Analysis Template

A deterministic rubric. Given the captured data and the frozen constants, it produces exactly one set of findings — every time. This is layer 2; for the manual pilot it makes your hand-analysis reproducible.

3 · The handoff — the Findings Object

The Analysis template emits exactly this structure: a fully-classified, LLM-free description of the student. The Report template may read it and phrase it — it may never add to it.

findings = {
  differentiation: { top_capacity:"empathy", second:"analytical", direction:"impact", market_stance:"holding_to_pull" },
  capacities: [ { name:"empathy", demonstrated:92, rank:1, is_spike:true, is_surprise:false }, … ],
  roles: [ { name:"researcher", frequency:0.9, tier:"demonstrated" }, … ],
  values: [ { name:"impact", rank:2, protected:true }, … ],
  project_pattern: { lead_impact:["ReVIVE"], outlier:"The Ibex", gap_note:"no community/children project" },
  conditions: { thrive:[…], wither:[…] },
  surprises: [ { trait:"storytelling", situations:4, confidence:"high" } ],
  gap: [ { capability:"field_research", current:0.2, desired:0.9, classification:"real", kind:"capability" }, … ],
  direction_check: { requires_capacities:["empathy","conviction","systems_sensing"], all_present:true, direction_blocked:false, capacity_gaps:[] },
  market: { wish_dir:"impact", actual_dir:"impact", pays_dir:"commercial_ui", market_gap:1.46, classification:"holding_to_pull" },
  experiments: [ { targets:"field_research", reason:"real_gap" }, { targets:"storytelling", reason:"claim_surprise" } ]
}
The hard boundary: if a fact isn't in the Findings Object, it cannot appear in the report. The Report template's prompt is given only this object — never the raw data — so the LLM literally cannot re-judge anything. It can't decide storytelling is a surprise; it's told so.
Part Two

The Report Template

A fixed structure, a fixed set of slots, and a strict contract. The LLM's entire job is to phrase the Findings Object into the slots — warmly, correctly, and within the rails below. This is layer 3.

1 · Fixed structure (never changes)

The report's sections and order are constant across every student — only the slot contents vary. (Matches the dashboard report.)

  • Hero — differentiation statement + vitals (computed flags, LLM phrases the one-liner)
  • Section 1 · Today — capacities · roles · values · project pattern · conditions
  • Surprise callout — confirm-question form
  • Section 2 · Heading — reach · gap · direction-vs-market · growth experiments
  • Appendix · Evidence Room — pure data table, no LLM

3 · The tone & rules contract

Stated verbatim in the system prompt. Violations are integrity failures, not style notes.

  • Never invent. Use only facts in the Findings Object. If a slot's finding is absent or low-confidence, say less — never fabricate to fill space.
  • No verdicts. Surprises and tensions are mirrors to confirm, not conclusions. Surprises end in a confirm-question.
  • Intra-individual only. Never compare the student to other students; no percentiles, no "above average."
  • As-of-today framing. Capacities are "thick today, built by your past, able to grow." Never "fixed," never "a scan shows."
  • Tier discipline. Neuroscience claims stay at the tier the finding carries (evidenced / well-motivated / plausible). Never upgrade a tier.
  • No invented market specifics. Recommendations give action types only — never specific certifications, salary figures, or named employers as if verified. Those are live market facts the instrument doesn't hold (and "what pays" is the student's belief to examine). Present specifics as "to research / verify," or defer to a real labour-market data source.
  • Classify before recommending. Never route a capacity gap to a course. Capability gaps → training; capacity gaps → cultivate-slowly / design-around / reconsider-direction.
  • Voice. Second person, warm, serious — not clinical, not bubbly. No emoji except the designated surprise ⚡.
  • Length. Respect each slot's word ceiling — the report is ~65% visual; prose is captions, not essays.

4 · Worked examples

differentiation_statement

✓ Good
"An empathy-led, analytical designer whose work reaches for impact — even when she frames herself for the market."Names top capacity + direction, ≤24 words, no comparison, true to the object.
✗ Bad
"One of the most empathetic designers in her cohort, with rare talent for impact work."Compares to others ("in her cohort"), "rare talent" is a verdict and not in the object.

surprise_phrasing

✓ Good
"In four situations your choices leaned on narrative — yet you never claimed storytelling. Strong in what you do, absent in what you say. Does that feel true?"States the computed finding, ends in a confirm-question.
✗ Bad
"You are secretly a natural storyteller — this is clearly your hidden superpower."Verdict, not a question; "clearly" overclaims a tentative, to-confirm finding.

experiment_text

✓ Good
"Run one project with a real community or children — the gap your portfolio is missing."Real-world action, targets the computed gap, no scoreboard.
✗ Bad
"Boost your field-research score to level 9 to outperform your peers."Scoreboard framing, comparison to peers, invents a numeric target.

5 · The repeatability guarantee

LayerGuarantees
Analysis engine (det.)Substantive consistency — same data → identical findings, classifications, numbers, every run.
Report template (contract)Equivalent meaning — the language may vary in wording but not in what it asserts; low temperature (≈0.3) tightens this further.
CacheByte-identical on re-view — generate once per report_instance, store the text, re-serve it. The LLM runs once, not per view.
The honest scope. Two fresh generations of the same student will phrase a finding differently ("reaches for impact" vs "drawn to impact work") — and that's fine: a report must be true and stable in substance, not byte-identical. Where byte-identity is needed (a student re-opening their report), the cache delivers it. Determinism on language comes from caching, not from fighting the model.
For the manual pilot. Today, you are the Analysis engine and Claude is the Synthesis layer with a loose contract — which is exactly why outputs vary. Use Part 1 as your hand-analysis rubric (so your findings are reproducible) and Part 2 as the prompt you give Claude (so it fills slots, not freelances). Then variation between runs stops being noise and becomes your signal for which scoring constants are still under-specified — the very numbers you'd otherwise be guessing at for the build.
